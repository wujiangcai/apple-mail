# 角色视角严格审计与操作清单

## 一、号商管理员视角

### 每日运营流程

1. 查看授权维护卡片，确认每日任务已运行；
2. 检查无效、忙碌、限流和失败数量；
3. 对 `token_valid=false` 的邮箱重新进行 Microsoft OAuth 授权；
4. 确认可出租邮箱库存；
5. 创建租约时选择邮箱或自动分配；
6. 交付租用码后，可通过完整租用码反查邮箱；
7. 售后需要时查看或重置租用码；
8. 不再经营的历史邮箱使用“停止出租”，不要删除。

### 授权维护说明

Microsoft access token 是短期令牌，不保存。每日任务使用 refresh token 换取临时 access token，并保存 Microsoft 轮换后的新 refresh token。

自动刷新不能修复 `invalid_grant`。出现无效授权时必须重新完成 OAuth 授权并更新邮箱记录。

### 常见风险

- 有效邮箱超过单批数量：系统会自动分页继续处理；
- Graph 429：任务尊重 Retry-After，并在结果中记录限流数量；
- 任务超过最大时长：状态为 partial，剩余邮箱下次优先补齐；
- 多个任务同时启动：数据库 advisory lock 只允许一个实例；
- 历史租约邮箱删除：系统永久禁止，避免售后关系丢失。

### 发布升级清单

1. 备份 PostgreSQL 和 Fernet 密钥；
2. 停止主服务或进入维护窗口；
3. 运行 `flask ... init-db`；
4. 运行测试；
5. 启动主服务；
6. 启用 refresh timer；
7. 检查管理员页和 `/pickup`；
8. 查看 systemd journal。

主服务重启不会自动运行 schema 迁移，避免每次启动锁表。

## 二、购买用户视角

### 正常取件流程

1. 访问 `/pickup`；
2. 输入租用码；
3. 查看当前邮箱、租约期限和短期会话剩余时间；
4. 在收件箱或垃圾邮件间切换；
5. 点击“刷新邮件”获取最新邮件；
6. 在当前文件夹提取验证码；
7. 会话到期后，永久租约可重新输入原码登录。

### 常见问题

- 找不到验证码：切换到垃圾邮件，再提取；
- 邮件还没出现：点击刷新邮件，确认目标网站已发送；
- 取件码失效：可能到期、撤销或已重置；
- 邮箱授权失效：联系管理员重新授权；
- Microsoft 限流：稍后再试；
- 永不过期租约：租约永久，但浏览器会话仍会过期。

### 隐私边界

购买用户只能看到分配邮箱的邮件、验证码、实时授权状态和当前保存的邮箱密码，不能看到：

- Client ID；
- refresh token；
- 其他邮箱；
- 其他租约；
- 管理员库存和审计数据。

邮件 HTML 在 sandbox iframe 中展示，验证码和邮件不会写入 Web Storage。

## 三、本轮修复摘要

- 垃圾邮件也可以直接提取验证码；
- 增加购买用户手动刷新邮件；
- 客户错误信息中文化；
- 会话不足 5 分钟时按秒倒计时；
- token 维护支持多批次覆盖全部有效邮箱；
- 并发 worker 配置正式生效；
- 维护任务尊重 Graph Retry-After；
- 超时任务记录 partial 和剩余数量；
- 增加最近维护结果 API 与管理员状态卡片；
- 增加过期会话、失败记录和 refresh lease 清理命令；
- 主服务重启不再自动执行 schema 迁移；
- 默认租期从服务器安全配置读取；
- 租用码展示文案与当前可查看/重置功能一致。
